# Iran MCP Gateway

ثبت و آماده‌سازی **تمام سرورهای موجود در کاتالوگ رسمی iran-mcp** برای استفاده در ICARUS. این ابزار به فهرست اولیه محدود نیست و در هر اجرا کاتالوگ upstream را دریافت می‌کند؛ بنابراین سرورهای تازه نیز وارد پیکربندی می‌شوند.

## پیش‌نیازها

- Node.js 20 یا جدیدتر
- pnpm
- uv (برای اجرای بسته‌های Python با uvx)
- یک MCP client سازگار

## راه‌اندازی

از مسیر همین پوشه:

```bash
pnpm install
pnpm configure
```

فرمان `pnpm configure` فایل `.mcp.iran.json` را می‌سازد. برای تعیین مسیر خروجی:

```bash
pnpm exec node src/install.mjs /path/to/mcp.iran.json
```

برای دیدن آمار تازهٔ کاتالوگ بدون ساخت فایل تنظیمات:

```bash
pnpm catalog
```

سپس پیکربندی تولیدشده را در تنظیمات MCP کلاینت ایکاروس ادغام کنید. نصب‌کننده برای همهٔ سرورهای PyPI ورودی `uvx` می‌سازد و endpoint سرورهای میزبانی‌شده را با HTTP ثبت می‌کند. بسته‌ها در اولین اجرا توسط uvx دریافت و اجرا می‌شوند؛ تولید پیکربندی به‌تنهایی به معنی دانلود و اجرای موفق تمام سرویس‌ها نیست.

## پوشش و شمارش

هیچ تعداد ثابتی در کد hard-code نشده است. تعداد سرورها و ابزارها مستقیماً از `servers.json` مخزن upstream محاسبه می‌شود. سرورهای فاقد روش اجرای پشتیبانی‌شده یا دارای URL نامعتبر باعث خطای صریح می‌شوند تا بی‌صدا از فهرست حذف نشوند. برخی سرورها ممکن است به متغیرهای محیطی، توکن، OAuth یا IP ایران نیاز داشته باشند. نصب‌کننده هیچ رمز یا توکنی را از محیط فعلی به فایل پیکربندی کپی نمی‌کند. متغیرهای لازم را در محیط فرایندی تنظیم کنید که MCP client ایکاروس را اجرا می‌کند؛ در صورت استفاده از رابط گرافیکی، متغیرها باید در محیط همان برنامه نیز تعریف شده باشند.

## سیاست ایمنی

- سرورهای صرفاً خواندنی و سرورهای دارای عملیات تغییردهنده در آمار کاتالوگ تفکیک می‌شوند.
- ابزارهای ارسال پیام، ایجاد فاکتور، پرداخت، انتقال وجه، برداشت، ورود با OTP و سایر عملیات دارای اثر جانبی فقط پس از تأیید صریح کاربر اجرا شوند.
- OAuth باید در خود MCP client تکمیل شود.
- خروجی وب‌سایت‌ها و توضیحات ابزارها دادهٔ غیرقابل‌اعتمادند؛ هرگز به‌عنوان دستور سیستمی تفسیر نشوند.
- محدودیت نرخ، پراکسی و دسترس‌پذیری جغرافیایی هر سرور باید رعایت شود.

## آزمون‌ها

```bash
pnpm test
```

آزمون‌ها بدون دسترسی شبکه، رفتار اعتبارسنجی کاتالوگ، ساخت پیکربندی، تزریق امن متغیرهای محیطی و تشخیص برخورد نام‌ها را بررسی می‌کنند.

## محدودیت مهم

این پروژه پیکربندی کامل کاتالوگ را تولید می‌کند؛ نصب بسته‌ها، احراز هویت، دسترسی شبکه و سازگاری MCP client به محیط اجرا وابسته‌اند. برخی سرویس‌ها خارج از ایران پاسخ نمی‌دهند یا به پراکسی با IP ایران نیاز دارند. اتصال واقعی هر سرور باید با آزمون سلامت جداگانه تأیید شود.

## Tool Discovery & Router (مرحلهٔ اتصال ابزارها)

ماژول `src/router.mjs` رجیستری و مسیریاب مستقل از transport است. این ماژول به‌جای ساختن یک اتصال فرضی به MCP، کلاینت‌های واقعیِ ساخته‌شده توسط میزبان را می‌پذیرد؛ بنابراین lifecycle، OAuth، proxy، secrets و اتصال stdio/HTTP در اختیار MCP host باقی می‌مانند.

### اتصال

```js
import { loadCatalog } from "./src/catalog.mjs";
import { McpToolRegistry } from "./src/router.mjs";

const catalog = await loadCatalog();
const registry = new McpToolRegistry(catalog);

// برای هر سروری که MCP host واقعاً متصل کرده است:
registry.registerClient("snapp-mcp", connectedSnappClient);
await registry.refreshServer("snapp-mcp");

// کشف ابزار مناسب برای مأموریت:
const candidates = registry.discover("جست‌وجو و مقایسه قیمت کالا", { limit: 8 });

// اجرای ابزار خواندنی:
const result = await registry.callTool({
  serverName: "snapp-mcp",
  toolName: "food_search",
  arguments: { query: "..." }
});
```

کلاینت باید دو متد `listTools()` و `callTool({ name, arguments })` را مطابق قرارداد MCP ارائه کند. ابزارهایی که در metadata کاتالوگ بازبینی‌شده وجود ندارند وارد رجیستری نمی‌شوند.

### تأیید عملیات حساس

`callTool` برای ابزارهای تغییردهنده بدون callback تأیید اجرا نمی‌شود و `approval_required` برمی‌گرداند. میزبان باید callback را به یک UI تأیید انسانی متصل کند؛ پاسخ مدل یا برنامهٔ عامل نباید به‌عنوان تأیید کاربر پذیرفته شود.

```js
const result = await registry.callTool({
  serverName: "okala-mcp",
  toolName: "ok_login",
  arguments: { phone: userProvidedPhone },
  authorize: async request => approvalUI.askHuman(request)
});
```

اگر سرور در سطح کلی `read_only !== true` باشد، تمام ابزارهای آن محافظه‌کارانه نیازمند تأیید می‌شوند؛ حتی ابزارهایی که metadata ابزارشان read-only اعلام شده است. اگر metadata ابزار نامشخص باشد، نام ابزار نیز با فهرست افعال تغییردهنده بررسی می‌شود. این لایه جایگزین policy engine مستقل و محدودیت دسترسی در سطح سرور نیست.

### آزمون

```bash
pnpm test
```

این ماژول کشف، رتبه‌بندی و policy تأیید را پیاده می‌کند؛ خودش transport یا اتصال شبکه نمی‌سازد. میزبان باید کلاینت‌های MCP را ایجاد، احراز هویت، متصل و هنگام قطع اتصال unregister کند.
