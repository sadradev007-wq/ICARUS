# معمار ایده (Idea Architect)

ابزار مستقل هارنس ایکاروس برای تبدیل ایده خام به برنامه پروژه، درخت وظایف و صف اجرای قابل اعتبارسنجی.

## وضعیت نسخه

**نسخه 0.1.0 — هسته برنامه‌ریزی و قرارداد JSON پیاده‌سازی شده است.**

این نسخه یک خط لوله قابل اجرا با مدل آزمایشی آفلاین دارد. اتصال به مدل‌های واقعی GGUF/Ollama/llama.cpp از طریق رابط `JsonModel` در گام بعدی انجام می‌شود؛ بنابراین هنوز ادعا نمی‌کنیم که مدل واقعی یا اجرای خودکار ابزارها متصل شده است.

## معماری

1. **Idea Input:** دریافت هدف خام و ایجاد شناسه پروژه.
2. **Skill Discovery:** جست‌وجوی اختیاری GitHub برای یافتن مهارت‌های مرتبط.
3. **System 1:** تولید طرح سطح بالا و وظایف اصلی؛ قابل اجرا با مدل محلی یا آفلاین.
4. **System 2:** گسترش بازگشتی هر وظیفه تا رسیدن به برگ اجرایی.
5. **Validation:** اعتبارسنجی قرارداد ITP و کنترل ساختار قبل از ذخیره.
6. **Execution Queue:** ساخت صف وظایف آماده بررسی؛ این نسخه هیچ فرمان یا کد خارجی را خودکار اجرا نمی‌کند.
7. **Project Persistence:** ذخیره ایده، طرح، صف و وضعیت پروژه در فایل‌های JSON.

مدل‌ها فقط پیشنهاد تولید می‌کنند. اعتبارسنجی، مجوزدهی و اجرای ابزارها مسئولیت کد میزبان است، نه خروجی مدل.

## پروتکل ITP-1.0

تمام خروجی‌های مدل باید یک JSON object معتبر باشند؛ متن توضیحی، Markdown fence یا محتوای اضافه پذیرفته نمی‌شود.

- `schemas/plan.schema.json`: قرارداد خروجی System 1.
- `schemas/expansion.schema.json`: قرارداد خروجی System 2.
- `protocol.py`: اعتبارسنجی زمان اجرا بدون وابستگی خارجی.

هر وظیفه System 2 باید `is_leaf` داشته باشد:
- اگر `is_leaf=true` باشد، باید `method`, `inputs`, `expected_outputs` و `acceptance_criteria` غیرخالی داشته باشد.
- اگر `is_leaf=false` باشد، System 2 دوباره برای همان وظیفه فراخوانی می‌شود.
- عمق تجزیه محدود است؛ وظایفی که تا سقف عمق اجرایی نشوند با `planning_blocked` علامت می‌خورند و وارد صف اجرا نمی‌شوند.

## اجرا در حالت آزمایشی آفلاین

به Python 3.10 یا جدیدتر نیاز است. از همین پوشه:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e .
icarus-idea "ساخت یک دستیار هوش مصنوعی آفلاین" --demo --projects ./Projects
python -m unittest discover -s tests
```

در ویندوز فعال‌سازی محیط مجازی با `.venv\\Scripts\\activate` انجام می‌شود.

حالت `--demo` از مدل قطعی آزمایشی استفاده می‌کند و برای بررسی جریان داده است، نه تولید برنامه واقعی با کیفیت LLM.

## اتصال مدل لوکال

یک کلاس از `JsonModel` مشتق کنید و متد `generate_json(role, system_prompt, payload)` را پیاده‌سازی کنید. آداپتر می‌تواند به Ollama، llama.cpp server یا موتور GGUF متصل شود. پاسخ خام مدل باید با `parse_json_object` تجزیه و سپس با اعتبارسنج مناسب بررسی شود. مدل باید نقش System 1 و System 2 را از طریق پارامتر `role` تشخیص دهد.

## کشف مهارت‌های GitHub

`GitHubSkillDiscovery` جست‌وجوی مخازن را انجام می‌دهد و `SkillRegistry` کاندیداها را در `quarantine/` ثبت می‌کند. این مرحله به اینترنت نیاز دارد؛ برنامه‌ریزی محلی به آن وابسته نیست.

**هیچ مخزن کشف‌شده‌ای خودکار نصب یا اجرا نمی‌شود.** قبل از فعال‌سازی یک مهارت باید مجوز، منبع، کد، وابستگی‌ها و رفتار آن بررسی و در sandbox آزمایش شود. توکن GitHub در صورت نیاز از کد فراخواننده تزریق می‌شود و نباید در فایل پروژه ذخیره شود.

## محدودیت‌های آگاهانه نسخه 0.1

- آداپتر واقعی LLM هنوز ارائه نشده است.
- اجرای ابزارها و Skillها هنوز پیاده‌سازی نشده؛ فقط صف اجرایی امن تولید می‌شود.
- اعتبارسنجی زمان اجرا با کد پایتون انجام می‌شود؛ برای اعتبارسنجی کامل JSON Schema می‌توان در آینده وابستگی اختیاری اضافه کرد.
- تأیید کاربر، بازیابی پس از crash، بازبرنامه‌ریزی بر اساس نتایج اجرا و UI در نسخه‌های بعدی توسعه می‌یابند.
